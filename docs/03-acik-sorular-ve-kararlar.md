# 03 · Açık Sorular ve Karar Kaydı

Her soru için **önerilen varsayılan** yazıldı. Karar verilince "Karar" sütunu doldurulur ve tasarım dokümanları güncellenir.

| # | Konu | Soru | Önerilen varsayılan | Karar |
|---|---|---|---|---|
| S1 | Ölçek ve kaynak | Kaç departman / servis / çalışan var? Mevcut bir İK sistemi (HRIS, bordro) var mı; organizasyon ve kişi verisi oradan mı gelecek? | Excel ile ilk yükleme, sonra düzenli CSV içe aktarma; API entegrasyonu 2. faz | |
| S2 | Davranışsal ölçek | Davranışsal yetkinlikler teknikle aynı 1–5 sayısal ölçeği mi kullansın? Seviye adları farklı olsun mu? | Aynı 1–5 sayı (katalizör analizi için şart), adlar farklı: Gelişmekte / Uygular / Güçlü / Rol model / Kültür taşıyıcı | |
| S3 | Değerlendirme kaynakları | Öz + yönetici yeterli mi? Akran/360 eklenecek mi (hangi yetkinlikler için)? Seviye 4–5 için üst doğrulama olsun mu? | Öz + yönetici zorunlu; 360 sadece davranışsal ve sadece yönetici rolleri için; 4–5 için üst yönetici doğrulaması | |
| S4 | Mutabakat ve itiraz | Anlaşmazlıkta nihai karar mercii kim? Fark kaç seviye olunca görüşme zorunlu? | Üst yönetici karar verir, İK gözlemci; kritik rollerde kalibrasyon komitesi; fark ≥ 2 → zorunlu görüşme | |
| S5 | Ücret/terfi bağlantısı | Değerlendirme sonuçları ücret, prim veya terfiye bağlanacak mı? Ne zaman? | İlk 2 döngü gelişim amaçlı ve ayrık; terfide "zorunlu beceri eşiği" 3. döngüden itibaren | |
| S6 | Hedef seviye düzeyi | Hedefler rol bazlı mı, pozisyon bazlı istisna olsun mu? Kademe (Uzman / Kıdemli / Baş) ayrımı var mı? | Rol bazlı + pozisyon istisnası; kademeler ayrı rol olarak tanımlanır | |
| S7 | Kritiklik | Kritik beceri/rol puanlamasını kim yapar? Eşik ve ağırlıklar? Kaç kritik rol bekleniyor? | Departman müdürü + İK birlikte; varsayılan ağırlıklar `02` dokümanında; kritik rol sayısı toplam rollerin %10–15'i | |
| S8 | Teknoloji | Web uygulaması mı, mobil de mi? Bulut mu kurum içi sunucu mu? SSO var mı (Microsoft 365 / Google)? Kullanıcı sayısı? Tercih edilen teknoloji var mı? | Web (mobil uyumlu); bulut; SSO varsa Entra ID; stack önerisi: TypeScript + React + PostgreSQL (karar sonrası netleşir) | |
| S9 | Eğitim kataloğu | Mevcut bir LMS / eğitim kataloğu var mı? Plan eylemleri buna bağlanacak mı? | Sistem içinde basit katalog; LMS varsa 2. fazda bağlantı | |
| S10 | KVKK ve gizlilik | Değerlendirme verisi kaç yıl saklanacak? Akran girdileri anonim mi? Çalışan kendi verisini dışa aktarabilsin mi? | 5 yıl saklama; akran anonim; çalışan kendi profilini PDF alabilir | |
| S11 | Potansiyel / 9-kutu | Performans puanı başka bir sistemden gelecek mi? 9-kutu isteniyor mu? | 9-kutu istenir; performans puanı İK tarafından elle girilir (1–5) | |
| S12 | Teknik beceri toplama | Şablon + çalıştay yeterli mi? Her servis için kaç beceri sınırı? Onay zinciri? | Şablon + 1 saatlik çalıştay/servis; 8–20 beceri; yönetici → İK → müdür onayı | |
| S13 | Döngü sıklığı | Yıllık ana + 6 aylık ara döngü uygun mu? İşe girişte 90 gün değerlendirmesi olsun mu? | Evet / Evet | |
| S14 | Dil | Sadece Türkçe mi, İngilizce de gerekli mi? | Türkçe; metinler çok dile hazır tasarlanır | |
| S15 | Mentorluk | Mentor eşleştirme sistemde resmi bir süreç olsun mu? Mentor başına limit? | Evet; mentor başına en fazla 3 menti | |
| S16 | Yetkinlik envanteri araması | Yöneticiler başka servislerdeki kişilerin beceri seviyelerini arayabilsin mi (proje kadrolama)? | Evet, sadece "seviye ≥ 3" bilgisiyle, puan detayı olmadan | |
